## HTTPメソッドとCRUD操作の対応

### REST APIの基本原則

REST（Representational State Transfer）では、HTTPメソッドとURL（エンドポイント）の組み合わせで操作を表現します。

| CRUD操作 | HTTPメソッド | エンドポイント | 説明 |
|---------|-------------|---------------|------|
| **C**reate | POST | `/api/v1/tasks` | 新しいタスクを作成 |
| **R**ead | GET | `/api/v1/tasks` | タスク一覧を取得 |
| **U**pdate | PATCH | `/api/v1/tasks/:id` | 特定のタスクを更新 |
| **D**elete | DELETE | `/api/v1/tasks/:id` | 特定のタスクを削除 |

### なぜHTTPメソッドが分かれているのか？

同じURL（`/api/v1/tasks`）でも、HTTPメソッドが違えば異なる操作を表現できます。

**例：**
- `GET /api/v1/tasks` → タスクを取得する（読み取り専用）
- `POST /api/v1/tasks` → タスクを作成する（データを変更）

これにより、URLを見ただけで「何を操作しているか」が分かり、HTTPメソッドで「どんな操作か」が分かります。

### 全体の流れ（7ステップ）

```
Step 1: ブラウザでフォーム入力
   ↓
```

### Step 1: ブラウザでフォーム入力

**ユーザーの操作：**
```

期日: 2025-12-15
優先度: high
```

**HTMLフォーム：**
```html

  <input type="date" name="due_date" value="2025-12-15">
```

フォームを送信すると、`POST /tasks/create` リクエストが task_api_tool に送られます。

### Step 2: Sinatraがフォーム受け取り

**ファイル：** `app.rb`

```ruby
post '/tasks/create' do
  # ① フォームデータを受け取る
  # params[:title] → "買い物に行く"
  # params[:due_date] → "2025-12-15"
  # params[:priority] → "high"

  # ② APIクライアントを初期化
  client = TaskApiClient.new

  # ③ Rails APIに送るデータを整形
  params_hash = {
    task: {
      title: params[:title],
      due_date: params[:due_date],
      priority: params[:priority]
    }
  }

  # ④ APIクライアントにタスク作成を依頼
  result = client.create_task(params_hash)

  # ⑤ 結果に応じてフラッシュメッセージを設定
  if result[:success]
    flash[:success] = "✅ タスクを作成しました！（ID: #{result[:task]['id']}）"
  else
    flash[:error] = "❌ #{result[:error]}"
  end

  # ⑥ トップページにリダイレクト
  redirect '/'
end
```

**ポイント：**
- `params` はフォームから送られたデータを格納するハッシュ
- `params_hash` はRails APIが期待する形式（`task[title]`のような入れ子構造）に整形
- `flash` はページ遷移後もメッセージを表示するための仕組み

---

### Step 3: APIクライアントがHTTPリクエスト送信

**ファイル：** `lib/task_api_client.rb`

```ruby
def create_task(params)
  # ① リクエストURLを作成
  uri = URI("#{BASE_URL}/tasks")
  # → http://localhost:3000/api/v1/tasks

  # ② HTTPクライアントを作成
  http = Net::HTTP.new(uri.host, uri.port)
  # → localhost:3000 に接続

  # ③ POSTリクエストを作成
  request = Net::HTTP::Post.new(uri.path, 'Content-Type' => 'application/json')
  # → ヘッダーに Content-Type: application/json を設定

  # ④ リクエストボディにJSONデータを設定
  request.body = params.to_json
  # → {"task":{"title":"買い物に行く","due_date":"2025-12-15","priority":"high"}}

  # ⑤ リクエストを送信してレスポンスを受け取る
  response = http.request(request)

  # ⑥ レスポンスを解析して返す
  parse_response(response)
end
```

**送信されるHTTPリクエスト：**
```http
POST /api/v1/tasks HTTP/1.1
Host: localhost:3000
Content-Type: application/json

{"task":{"title":"買い物に行く","due_date":"2025-12-15","priority":"high"}}
```

**ポイント：**
- `Net::HTTP` はRuby標準ライブラリのHTTPクライアント
- `to_json` でRubyのHashをJSON文字列に変換
- `Content-Type: application/json` でJSON形式であることを通知

### Step 4: Rails APIがリクエスト処理

**ファイル：** `task_learning_app/app/controllers/api/v1/tasks_controller.rb`

```ruby
def create
  # ① Strong Parametersでパラメータを検証
  # task_params → { title: "買い物に行く", due_date: "2025-12-15", priority: "high" }

  # ② 新しいTaskオブジェクトを作成
  @task = Task.new(task_params)

  # ③ データベースに保存を試みる
  if @task.save
    # ④-a 保存成功：201 Created レスポンスを返す
    render json: { task: @task }, status: :created
  else
    # ④-b 保存失敗：422 Unprocessable Entity レスポンスを返す
    render json: { errors: @task.errors.full_messages }, status: :unprocessable_entity
  end
end

private

def task_params
  # 許可されたパラメータのみを受け入れる（セキュリティ対策）
  params.require(:task).permit(:title, :due_date, :priority, :project_id)
end
```

**ポイント：**
- **Strong Parameters**：SQLインジェクション対策。許可されたパラメータのみを受け入れる
- `@task.save` でデータベースに保存
- `render json:` でJSONレスポンスを返す

### Step 5: データベースに保存

**ファイル：** `task_learning_app/app/models/task.rb`

```ruby
class Task < ApplicationRecord
  # バリデーション（データの妥当性チェック）
  validates :title, presence: true
  validates :due_date, presence: true

  # priorityのデフォルト値
  attribute :priority, :string, default: 'medium'
end
```

**データベーステーブル（tasksテーブル）：**

| カラム名 | データ型 | 説明 |
|---------|---------|------|
| id | integer | 主キー（自動採番） |
| title | string | タスクのタイトル |
| due_date | date | 期日 |
| priority | string | 優先度 (low/medium/high) |
| project_id | integer | プロジェクトID（外部キー） |
| completed_at | datetime | 完了日時 |
| deleted_at | datetime | 削除日時（論理削除） |
| created_at | datetime | 作成日時（自動設定） |
| updated_at | datetime | 更新日時（自動設定） |

**保存されるデータ：**
```sql
INSERT INTO tasks (title, due_date, priority, created_at, updated_at)
VALUES ('買い物に行く', '2025-12-15', 'high', '2025-12-13 12:00:00', '2025-12-13 12:00:00');
```

**ポイント：**
- `validates` でバリデーションルールを定義
- タイトルと期日が空の場合は保存失敗（`@task.save` が `false` を返す）
- `created_at` と `updated_at` はActiveRecordが自動的に設定

### Step 6: JSONレスポンス返却

**成功時のレスポンス（201 Created）：**
```json
{
  "task": {
    "id": 123,
    "title": "買い物に行く",
    "due_date": "2025-12-15",
    "priority": "high",
    "project_id": null,
    "completed_at": null,
    "deleted_at": null,
    "created_at": "2025-12-13T12:00:00.000Z",
    "updated_at": "2025-12-13T12:00:00.000Z"
  }
}
```

**失敗時のレスポンス（422 Unprocessable Entity）：**
```json
{
  "errors": [
    "タイトルを入力してください",
    "期日を入力してください"
  ]
}
```

**task_api_clientでのレスポンス解析：**

```ruby
def parse_response(response)
  if response.is_a?(Net::HTTPSuccess)
    # 成功時（200 OK, 201 Created）
    data = JSON.parse(response.body)
    { success: true, task: data['task'] }
  elsif response.code.to_i == 422
    # バリデーションエラー
    data = JSON.parse(response.body)
    { success: false, errors: data['errors'] }
  else
    # その他のエラー
    { success: false, error: "HTTPエラー: #{response.code}" }
  end
end
```

**ポイント：**
- HTTPステータスコードで成功/失敗を判定
- `JSON.parse` でJSON文字列をRubyのHashに変換
- 統一された形式（`{ success: true/false, ... }`）で返す

## エラーハンドリングの仕組み

### エラーの種類と対処

| エラーの種類 | HTTPステータス | 発生場所 | 原因 | 対処 |
|-------------|---------------|---------|------|------|
| ネットワークエラー | - | task_api_client.rb | task_learning_appが起動していない | `Errno::ECONNREFUSED` をrescue |
| Not Found | 404 | Rails API | 指定されたIDのタスクが存在しない | `response.code.to_i == 404` で判定 |
| バリデーションエラー | 422 | Rails API | タイトルや期日が空欄 | `response.code.to_i == 422` で判定 |
| サーバーエラー | 500 | Rails API | サーバー内部でエラー発生 | `else` 節で汎用エラー処理 |

### エラーハンドリングのコード例

```ruby
def fetch_tasks
  uri = URI("#{BASE_URL}/tasks")
  response = Net::HTTP.get_response(uri)

  if response.is_a?(Net::HTTPSuccess)
    # 成功時の処理
    data = JSON.parse(response.body)
    { success: true, tasks: data['tasks'] }
  else
    # HTTPエラー
    { success: false, error: "HTTPエラー: #{response.code} #{response.message}" }
  end
rescue Errno::ECONNREFUSED
  # 接続エラー
  { success: false, error: "APIサーバーに接続できません。task_learning_appが起動しているか確認してください。" }
rescue JSON::ParserError => e
  # JSONパースエラー
  { success: false, error: "JSONの解析に失敗しました: #{e.message}" }
rescue => e
  # その他のエラー
  { success: false, error: "エラーが発生しました: #{e.message}" }
end
```

## よくある質問

### Q1: なぜJSONを使うのか？

**A:** JSONはテキスト形式のデータフォーマットで、以下の利点があります：

- **言語非依存**：RubyでもJavaScriptでも読み書きできる
- **人間が読みやすい**：構造が分かりやすい
- **軽量**：ネットワーク転送に適している
- **Webの標準**：ほぼすべてのプログラミング言語がサポート

**JSON形式の例：**
```json
{
  "task": {
    "id": 1,
    "title": "買い物に行く",
    "due_date": "2025-12-15"
  }
}
```

---

### Q2: task[title]の`[]`の意味は？

**A:** これはRailsのパラメータの入れ子構造を表す記法です。

**HTMLフォーム：**
```html
<input name="task[title]" value="買い物に行く">
<input name="task[due_date]" value="2025-12-15">
```

**Railsで受け取るparams：**
```ruby
{
  task: {
    title: "買い物に行く",
    due_date: "2025-12-15"
  }
}
```

これにより、関連するパラメータをグループ化できます。

---

### Q3: なぜ2つのサーバーが必要なのか？

**A:** それぞれ異なる役割を持つためです：

| サーバー | 役割 | 責務 |
|---------|------|------|
| task_api_tool | **UIレイヤー** | ユーザーインターフェース、HTMLレンダリング |
| task_learning_app | **APIレイヤー** | ビジネスロジック、データ永続化 |

**利点：**
- **関心の分離**：UIとビジネスロジックを独立させる
- **再利用性**：Rails APIは他のクライアント（モバイルアプリなど）からも利用可能
- **保守性**：それぞれ独立して開発・修正できる

---

### Q4: GETとPOSTの違いは？

**A:** データの扱い方が異なります：

| 項目 | GET | POST |
|------|-----|------|
| **用途** | データの取得（Read） | データの作成・変更 |
| **データの送り方** | URL（クエリストリング） | リクエストボディ |
| **ブックマーク** | 可能 | 不可 |
| **データの長さ制限** | あり（URLの長さ制限） | なし |
| **冪等性** | あり（何度実行しても同じ結果） | なし（実行するたびに新しいデータが作られる） |

**GETの例：**
```
GET /api/v1/tasks?priority=high
```

**POSTの例：**
```
POST /api/v1/tasks
Body: {"task":{"title":"買い物に行く"}}
```

---

### Q5: HTTPステータスコードの意味は？

**A:** サーバーがクライアントにレスポンスの結果を伝えるコードです：

| コード | 意味 | 説明 | 例 |
|-------|------|------|---|
| **200** | OK | 成功 | GET, PATCHの成功時 |
| **201** | Created | 作成成功 | POSTでタスク作成成功 |
| **404** | Not Found | 見つからない | 存在しないIDを指定 |
| **422** | Unprocessable Entity | バリデーションエラー | タイトルが空欄 |
| **500** | Internal Server Error | サーバーエラー | サーバー内部で例外発生 |

## まとめ

### 重要なポイント

1. **REST APIの基本**：HTTPメソッド（GET/POST/PATCH/DELETE）とURL（エンドポイント）の組み合わせで操作を表現
2. **JSONデータ形式**：サーバー間のデータのやり取りはJSON形式
3. **クライアント・サーバーモデル**：ブラウザ → task_api_tool → task_learning_app → DB という流れ
4. **エラーハンドリング**：HTTPステータスコードとrescue節で適切にエラーを処理
5. **バリデーション**：データの妥当性をチェックし、不正なデータの保存を防ぐ
