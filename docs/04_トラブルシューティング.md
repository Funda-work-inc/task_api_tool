# 04_トラブルシューティング

このドキュメントでは、Task API Toolを使用する際によく発生する問題とその解決方法を紹介します。

## 起動時の問題

### 問題1: `bundle install`が失敗する

**エラーメッセージ例：**
```
Gem::FilePermissionError: You don't have write permissions
```

**原因：**
- Rubyやgemのインストールディレクトリに書き込み権限がない
- システムのRubyを使用している

**解決方法：**

#### 方法1: rbenvを使用してユーザー領域にRubyをインストール
```bash
$ rbenv install 3.3.0
$ rbenv local 3.3.0
$ bundle install
```

#### 方法2: `--path vendor/bundle`を使用
```bash
$ bundle install --path vendor/bundle
```

---

### 問題2: `ruby app.rb`が起動しない

**エラーメッセージ例：**
```
cannot load such file -- sinatra (LoadError)
```

**原因：**
- `bundle install`が実行されていない
- Rubyのバージョンが異なる

**解決方法：**

#### Step 1: `bundle install`を実行
```bash
$ bundle install
```

#### Step 2: `bundle exec`を使って起動
```bash
$ bundle exec ruby app.rb
```

---

### 問題3: ポート4567が既に使用されている

**エラーメッセージ例：**
```
Errno::EADDRINUSE: Address already in use - bind(2) for 127.0.0.1:4567
```

**原因：**
- 既に別のプロセスがポート4567を使用している
- 前回のtask_api_toolが正しく終了していない

**解決方法：**

#### 方法1: 既存のプロセスを終了
```bash
# ポート4567を使用しているプロセスを探す
$ lsof -i :4567

# 表示されたPIDを確認して、killコマンドで終了
$ kill -9 <PID>
```

#### 方法2: 別のポートで起動
```bash
# app.rbを編集（最後に以下を追加）
set :port, 4568

# または、環境変数で指定
$ PORT=4568 ruby app.rb
```

## API通信の問題

### 問題4: "APIサーバーに接続できません"と表示される

**エラーメッセージ：**
```
⚠️ エラーが発生しました
APIサーバーに接続できません。task_learning_appが起動しているか確認してください。
```

**原因：**
- task_learning_appが起動していない
- task_learning_appが別のポートで起動している
- ファイアウォールがローカル通信をブロックしている

**解決方法：**

#### Step 1: task_learning_appが起動しているか確認
別のターミナルウィンドウで確認：
```bash
$ curl http://localhost:3000/api/v1/tasks
```

**期待される結果：**
```json
{"tasks":[...]}
```

**接続できない場合：**
```
curl: (7) Failed to connect to localhost port 3000: Connection refused
```

#### Step 2: task_learning_appを起動
```bash
$ cd /Users/fukumotokichiyou/task_learning_app
$ bin/rails server
```

#### Step 3: ブラウザで再読み込み
`http://localhost:4567` で「🔄 再読み込み」ボタンをクリック

---

### 問題5: タスク一覧が空のまま

**症状：**
- エラーメッセージは表示されない
- 「📝 タスクがありません」と表示される
- 実際にはタスクが登録されているはず

**原因：**
- データベースに本当にタスクが存在しない
- `deleted_at`が設定されている（論理削除済み）
- 別のデータベースを参照している

**解決方法：**

#### Step 1: Railsコンソールでデータベースを確認
```bash
$ cd /Users/fukumotokichiyou/task_learning_app
$ bin/rails console

# タスクの総数を確認
irb> Task.count
=> 0  # タスクが存在しない

# 削除済みタスクを含めて確認
irb> Task.with_deleted.count
=> 5  # 削除済みタスクが5件存在
```

#### Step 2: タスクを作成
```ruby
irb> Task.create(title: "テストタスク", due_date: Date.today)
```

#### Step 3: ブラウザで再読み込み

### 問題6: タスクが作成できない（バリデーションエラー）

**エラーメッセージ例：**
```
❌ タイトルを入力してください, 期日を入力してください
```

**原因：**
- 必須項目（タイトル、期日）が空欄
- フォームの送信に失敗している

**解決方法：**

#### Step 1: 必須項目をすべて入力
- **タイトル**：必ず入力する
- **期日**：カレンダーから選択する

#### Step 2: ブラウザのDevToolsでエラーを確認
1. ブラウザでF12キーを押す
2. Consoleタブを開く
3. エラーメッセージを確認

---

### 問題7: タスクの更新・削除ができない（404エラー）

**エラーメッセージ例：**
```
❌ タスクが見つかりません
```

**原因：**
- 指定されたIDのタスクが存在しない
- タスクが既に削除されている（論理削除）
- 別のデータベースを参照している

**解決方法：**

#### Step 1: 最新のタスク一覧を確認
「🔄 再読み込み」ボタンをクリックして、現在存在するタスクのIDを確認

#### Step 2: 存在するタスクIDを指定
ドロップダウンメニューから、実際に表示されているタスクを選択

#### Step 3: Railsコンソールで確認
```bash
$ bin/rails console

# タスクが存在するか確認
irb> Task.find(123)
ActiveRecord::RecordNotFound: Couldn't find Task with 'id'=123
# → タスクが存在しない

# 削除済みタスクも含めて検索
irb> Task.with_deleted.find(123)
=> #<Task id: 123, deleted_at: "2025-12-13 12:00:00">
# → 削除済みタスク
```

- 画面が真っ白で、装飾がない
- テーブルが見づらい

- CSSファイルが読み込まれていない

- ファイルパスが間違っている

**解決方法：**

#### Step 1: CSSファイルの存在を確認
```bash
$ ls -la /Users/fukumotokichiyou/task_api_tool/public/css/style.css
```

ファイルが存在しない場合：
```bash
$ mkdir -p public/css
# style.cssを作成する
```

#### Step 2: ブラウザのDevToolsでエラーを確認
1. F12キーを押す
2. Networkタブを開く
3. ページをリロード
4. `style.css`が404エラーになっていないか確認

#### Step 3: Sinatraの静的ファイル設定を確認
`app.rb`に以下が記述されているか確認：
```ruby
# デフォルトでpublicディレクトリが静的ファイルのルートになる
# 特別な設定は不要
```

### 問題9: タブが切り替わらない

**症状：**
- タブボタンをクリックしても、フォームが切り替わらない
- JavaScriptエラーが発生している

**原因：**
- JavaScriptが正しく動作していない
- ブラウザがJavaScriptをブロックしている

**解決方法：**

#### Step 1: ブラウザのConsoleでエラーを確認
1. F12キーを押す
2. Consoleタブを開く
3. JavaScriptエラーがないか確認

**よくあるエラー：**
```
Uncaught ReferenceError: showTab is not defined
```

#### Step 2: `views/index.erb`にJavaScriptが含まれているか確認
ファイル末尾に以下のような`<script>`タグがあるか確認：
```html
<script>
function showTab(tabName) {
  // タブ切り替えのコード
}
</script>
```

#### Step 3: ブラウザのキャッシュをクリア
1. Ctrl + Shift + R（Windows/Linux）
2. Cmd + Shift + R（Mac）

## データベースの問題

### 問題10: データベースがロックされている

**エラーメッセージ例：**
```
SQLite3::BusyException: database is locked
```

**原因：**
- 複数のプロセスが同時にデータベースにアクセスしている
- Railsコンソールやテストが実行中

**解決方法：**

#### Step 1: Railsコンソールやテストを終了
```bash
# Railsコンソールを終了
irb> exit

# テストを中断
Ctrl + C
```

#### Step 2: task_learning_appを再起動
```bash
# 一度停止
Ctrl + C

# 再起動
$ bin/rails server
```

---

### 問題11: マイグレーションが適用されていない

**エラーメッセージ例：**
```
ActiveRecord::StatementInvalid: SQLite3::SQLException: no such column: tasks.deleted_at
```

**原因：**
- データベースのマイグレーションが実行されていない
- 古いデータベースファイルを使用している

**解決方法：**

#### Step 1: マイグレーションステータスを確認
```bash
$ cd /Users/fukumotokichiyou/task_learning_app
$ bin/rails db:migrate:status
```

#### Step 2: マイグレーションを実行
```bash
$ bin/rails db:migrate
```

#### Step 3: 開発環境をリセット（最終手段）
```bash
$ bin/rails db:reset
# データベースを削除して再作成し、マイグレーションとシードを実行
```

## その他の問題

### 問題12: フラッシュメッセージが表示されない

**症状：**
- タスクを作成・更新・削除しても、成功メッセージが表示されない

**原因：**
- セッションが無効になっている
- `app.rb`でセッションが有効化されていない

**解決方法：**

#### `app.rb`を確認
```ruby
# セッションを有効化（必須）
enable :sessions
```

この行が存在しない場合は追加して、task_api_toolを再起動。

---

### 問題13: タスク作成後、タスク一覧に反映されない

**症状：**
- 成功メッセージは表示される
- でもタスク一覧には表示されない

**原因：**
- ブラウザのキャッシュが古い
- データベースには保存されているが、表示処理に問題がある

**解決方法：**

#### Step 1: 強制リロード
- Ctrl + Shift + R（Windows/Linux）
- Cmd + Shift + R（Mac）

#### Step 2: Railsコンソールで確認
```bash
$ bin/rails console

# 最新のタスクを取得
irb> Task.last
=> #<Task id: 123, title: "買い物に行く", ...>
```

データベースに保存されていれば、表示処理の問題。
保存されていなければ、API呼び出しの問題。

## トラブルシューティングの基本フロー

問題が発生した時は、以下の順番で確認してください：

### 1. エラーメッセージを読む
エラーメッセージには解決のヒントが含まれています。

### 2. ブラウザのDevToolsを確認
- **Console**: JavaScriptエラー
- **Network**: HTTPリクエスト/レスポンス
- **Elements**: HTML/CSSの状態

### 3. ログを確認
```bash
# task_api_toolのログ（ターミナルに表示）
# task_learning_appのログ
$ tail -f log/development.log
```

### 4. 段階的に切り分ける
1. **ネットワーク**: task_learning_appに直接アクセスできるか？
   ```bash
   $ curl http://localhost:3000/api/v1/tasks
   ```
2. **データベース**: データは保存されているか？
   ```bash
   $ bin/rails console
   irb> Task.last
   ```
3. **ブラウザ**: JavaScriptエラーはないか？
   F12 → Console

### 5. 再起動してみる
意外と多くの問題が再起動で解決します：
```bash
# task_api_toolを再起動
Ctrl + C
$ ruby app.rb

# task_learning_appを再起動
Ctrl + C
$ bin/rails server
```

## まとめ

### よくある問題トップ3

1. **task_learning_appが起動していない** → `bin/rails server`で起動
2. **bundle installを忘れている** → `bundle install`を実行
3. **ポートが衝突している** → `lsof -i :4567`で確認して終了

### トラブルシューティングのコツ

- **焦らない**：エラーメッセージを落ち着いて読む
- **切り分ける**：問題がどこで発生しているか特定する
- **ログを見る**：ログには多くの情報が含まれている
- **再起動する**：意外と解決することが多い
