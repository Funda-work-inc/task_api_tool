#### 1-1. Webhook受信エンドポイント実装

**実装ファイル**: `app.rb`（123-161行目）

**実装コード**:
```ruby
post '/webhook' do
  request.body.rewind
  payload = JSON.parse(request.body.read)

  puts "=" * 50
  puts "🔔 Webhook受信！"
  puts "イベント: #{payload['event']}"
  puts "タスクID: #{payload['task']['id']}"
  puts "タスク名: #{payload['task']['title']}"
  puts "発生時刻: #{payload['timestamp']}"
  puts "=" * 50

  session[:webhook_logs] ||= []
  session[:webhook_logs].unshift({
    event: payload['event'],
    task: payload['task'],
    timestamp: payload['timestamp']
  })
  session[:webhook_logs] = session[:webhook_logs].first(10)

  status 200
  content_type :json
  { success: true, message: "Webhook received" }.to_json
rescue JSON::ParserError => e
  status 400
  content_type :json
  { success: false, error: "Invalid JSON: #{e.message}" }.to_json
rescue => e
  status 500
  content_type :json
  { success: false, error: "Server error: #{e.message}" }.to_json
end

get '/webhooks' do
  @webhook_logs = session[:webhook_logs] || []
  erb :webhooks
end
```

**設計ポイント**:
- `request.body.rewind`でボディを最初から読み直し
- `JSON.parse`でペイロード解析
- `puts`でコンソールに整形出力
- セッションに履歴を保存（最新10件のみ）
- エラーハンドリングで3種類のケースに対応

#### 2-2. Webhookエンドポイントのテスト作成

**追加ファイル**: `spec/webhook_spec.rb`

**テストケース**:
1. **正常なWebhookペイロードの場合**
   - 200 OKを返す
   - 成功レスポンスを返す
   - Content-Typeがapplication/jsonである

2. **不正なJSONの場合**
   - 400 Bad Requestを返す
   - エラーメッセージを含む

3. **各イベントタイプのWebhookの場合**
   - createdイベントを正常に受信する
   - updatedイベントを正常に受信する
   - destroyedイベントを正常に受信する

4. **GET /webhooks**
   - 200 OKを返す

**テストコード例**:
```ruby
describe 'POST /webhook' do
  let(:valid_payload) do
    {
      event: 'created',
      task: {
        id: 1,
        title: 'テストタスク',
        priority: 'high',
        due_date: '2025-12-21',
        completed_at: nil,
        created_at: '2025-12-14T12:00:00Z',
        updated_at: '2025-12-14T12:00:00Z'
      },
      timestamp: '2025-12-14T12:00:00Z'
    }
  end

  context '正常なWebhookペイロードの場合' do
    it '200 OKを返す' do
      post '/webhook', valid_payload.to_json, { 'CONTENT_TYPE' => 'application/json' }
      expect(last_response.status).to eq(200)
    end

    it '成功レスポンスを返す' do
      post '/webhook', valid_payload.to_json, { 'CONTENT_TYPE' => 'application/json' }
      expect(last_response.body).to include_json(
        success: true,
        message: 'Webhook received'
      )
    end
  end
end
```

## 💡 技術的決定事項（Decision Log）

### 決定1: Sinatraでの実装

**決定内容**: Webhook受信機能をSinatraで実装

**理由**:
1. task_api_tool が既にSinatraで構築されている
2. 軽量で高速なWebhook受信に適している
3. シンプルなエンドポイント実装が可能

**代替案と不採用理由**:
- Railsで実装: オーバースペックで複雑すぎる

---

### 決定2: セッション保存による履歴管理

**決定内容**: Webhook履歴をセッションに保存（最新10件）

**理由**:
1. 学習目的のため、まずはシンプルに実装
2. データベース不要で高速
3. メモリ使用量が少ない

**代替案と不採用理由**:
- DB永続化: 初期実装では不要。将来的に拡張可能

---

### 決定3: コンソールログ出力

**決定内容**: 受信したWebhookをコンソールに整形して出力

**理由**:
1. 開発・デバッグがしやすい
2. ログファイルへの永続化は後回し
3. 視覚的に分かりやすい

## 🎓 学習ポイント

### 1. Sinatraでのエンドポイント実装

**学んだこと**:
- `post '/path'`でPOSTエンドポイントを定義
- `request.body`でリクエストボディを取得
- `status`でHTTPステータスを指定
- `content_type :json`でContent-Typeを指定

**実務での応用**:
- 軽量なAPIサーバーの構築
- Webhookレシーバーの実装
- マイクロサービスのエンドポイント

---

### 2. JSONペイロードの解析

**学んだこと**:
- `JSON.parse`でJSON文字列をHashに変換
- `rescue JSON::ParserError`で不正なJSONをキャッチ
- ペイロードの各フィールドにアクセス（`payload['event']`）

**注意点**:
- パースエラーは必ず処理すること
- 不正なJSONでサーバーがクラッシュしないようにする

---

### 3. Rack::Testでのテスト

**学んだこと**:
- `post '/path', json_data, headers`でHTTPリクエストをシミュレート
- `last_response`で直前のレスポンスを取得
- `expect(last_response.status).to eq(200)`でステータスコードを検証
- `include_json`でJSONレスポンスの部分一致検証

**ベストプラクティス**:
- テストデータは`let`で定義して再利用
- 正常系と異常系の両方をテスト
- エラーケースも必ずテストする

---

### 4. 開発ワークフローの重要性

**学んだこと（反省を含む）**:
- 実装前にテストを書くことで設計が明確になる（TDD）
- ドキュメント作成は実装と同じく重要

**今後の改善**:
