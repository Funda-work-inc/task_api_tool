## 🎯 企画書（ライト）

### プロジェクトの目的
Webhook受信履歴の視認性と利便性を向上させるため、トップページでの表示、リアルタイム自動更新、詳細情報の表示を実装する。

### ターゲットユーザー
- task_api_toolを利用する開発者（自分自身）
- Webhookイベントをリアルタイムで監視したい開発者

### 解決したい課題
1. **視認性の問題**: Webhook履歴が`/webhooks`ページでしか見られない
2. **リアルタイム性の欠如**: 手動でページをリロードしないと最新情報が見られない
3. **情報不足**: 表示される情報が最小限で、詳細が分かりにくい

### プロジェクトのスコープ

#### スコープイン（実装する機能）
- トップページ（/）にWebhook履歴セクションを表示
- JavaScriptポーリングによるリアルタイム自動更新（10秒ごと）
- 詳細情報の表示（イベント種別、タイムスタンプ、タスク詳細）
- イベント種別の色分け表示（作成・更新・削除）
- タイムスタンプの「〇〇秒前」形式表示
- JSON APIエンドポイント（/api/webhook_logs）

#### スコープアウト（実装しない機能）※現時点
- WebSocketによるリアルタイム通信
- Webhook履歴のエクスポート機能
- フィルター機能（イベント種別で絞り込み）
- 通知音やアニメーション

### 成功指標
- トップページでWebhook履歴が正しく表示される
- 10秒ごとに自動で最新情報が更新される
- イベント種別が色分けされて見やすい
- 全てのテストが通る

### 要求の背景・理由

#### R1-R2: トップページ表示（Must）
- **背景**: 毎回`/webhooks`ページに移動するのが手間
- **理由**: トップページで一目で確認できれば利便性が向上
- **期待効果**: Webhook監視の効率化

#### R3-R4: リアルタイム自動更新（Must）
- **背景**: 手動でリロードするのが面倒
- **理由**: Webhookイベントはリアルタイムで発生するため、自動更新が必要
- **期待効果**: 常に最新情報を把握できる

#### R5-R7: 詳細情報表示（Must）
- **背景**: イベント種別やタイムスタンプが分かりにくい
- **理由**: 視認性を向上させるため
- **期待効果**: 一目で状況を把握できる

#### R8: JSON APIエンドポイント（Must）
- **背景**: JavaScriptからWebhook履歴を取得する仕組みが必要
- **理由**: リアルタイム更新機能を実現するため
- **期待効果**: 非同期通信による快適なUX

### 要件詳細

#### F1: トップページにWebhook履歴セクション表示
- **対応要求**: R1（トップページ表示）
- **要件内容**: トップページにWebhook履歴を表示するセクションを追加
- **実装方法**:
  - `views/index.erb`の最後に`<div class="webhook-section">`を追加
  - テーブル形式で履歴を表示
  - JavaScriptで動的に内容を更新
- **画面要素**: イベント種別、タスクID、タスク名、優先度、期日、受信時刻

#### F2: JavaScript自動更新機能
- **対応要求**: R3, R4（リアルタイム更新）
- **要件内容**: ページをリロードせずに、10秒ごとにWebhook履歴を自動更新
- **実装方法**:
  - `fetchWebhookLogs()`関数でJSON APIを呼び出し
  - `setInterval(fetchWebhookLogs, 10000)`で10秒ごとに実行
  - `fetch('/api/webhook_logs')`でAPIリクエスト
- **理由**: ポーリング方式はシンプルで実装が容易、サーバー負荷も低い

#### F6: GET /api/webhook_logs エンドポイント
- **対応要求**: R8（JSON API）
- **要件内容**: Webhook履歴をJSON形式で返すAPIエンドポイント
- **実装方法**:
  - `app.rb`に`get '/api/webhook_logs'`ルーティング追加
  - セッションから履歴を取得: `session[:webhook_logs] || []`
  - JSON形式で返す: `{ webhook_logs: webhook_logs }.to_json`
- **動作**: セッションに保存されたWebhook履歴を全て返す

### 非機能要件詳細

#### N1: レスポンス時間
- **目標**: ポーリング間隔10秒で過負荷にならない
- **対策**:
  - ポーリング間隔を10秒に設定（頻繁すぎない）
  - JSON APIは軽量（セッションから読み取るだけ）
  - セッションは最大10件まで保持

#### N2: ブラウザ互換性
- **目標**: モダンブラウザで動作する
- **対策**:
  - fetch API使用（IE11非対応だが、モダンブラウザでは標準）
  - ES6構文使用（アロー関数、テンプレートリテラル）
