# プロジェクト企画書：Task API Tool

## 1. プロジェクト概要

### プロジェクト名
**Task API Tool - REST API 視覚的テストツール**

### 作成日
2025年12月13日

### プロジェクトの目的
task_learning_app の REST API をブラウザから視覚的にテストできる WebUI ツールを開発する。初心者でも簡単に API の動作を確認でき、REST API の仕組みを学習できる環境を提供する。

### 背景・課題
- REST API をテストするには、curlコマンドやPostmanなどの専門ツールが必要で、初心者には敷居が高い
- API の動作確認に時間がかかり、開発効率が低下している
- API の仕組み（HTTPメソッド、JSON、エンドポイント）を理解するための教材が不足している

### 解決策
ブラウザベースの直感的な WebUI を提供し、フォーム入力だけで API のテストができるツールを開発する。また、詳細な解説ドキュメントを用意し、初心者の学習をサポートする。

### ターゲットユーザー
- プログラミング初心者（API の基礎を学びたい方）
- Web 開発を学びたい方（REST API の仕組みを実践的に理解したい方）
- task_learning_app の開発者（API の動作確認を効率化したい方）

## 2. 要求定義（MoSCoW分析）

### Must Have（必須要件）
1. **タスク一覧の表示機能**
   - task_learning_app から取得したタスクをテーブル形式で表示
   - 表示項目：ID、タイトル、期日、優先度、完了状態、作成日時

2. **タスク作成機能**
   - フォームからタスクを新規作成
   - 入力項目：タイトル（必須）、期日（必須）、優先度、プロジェクトID

3. **タスク更新機能**
   - 既存タスクの情報を部分更新
   - 変更したい項目のみを送信可能

4. **タスク削除機能**
   - タスクを削除（論理削除）
   - 削除前に確認ダイアログを表示

5. **エラーハンドリング**
   - API接続エラー、バリデーションエラー、HTTPエラーを適切に処理
   - ユーザーにわかりやすいエラーメッセージを表示

### Should Have（実装すべき要件）
1. **フラッシュメッセージ機能**
   - 操作結果（成功/失敗）をユーザーに通知

2. **タブ切り替えUI**
   - 作成/更新/削除のフォームをタブで切り替え

3. **レスポンシブデザイン**
   - モバイル端末でも使いやすいUI

4. **詳細ドキュメント（5ファイル）**
   - はじめに、セットアップガイド、使い方ガイド、仕組み解説、トラブルシューティング

### Could Have（あれば良い要件）
1. **タスク検索機能**
   - キーワードや優先度でフィルタリング

2. **タスク完了機能**
   - タスクを完了状態に変更

3. **バッチ操作**
   - 複数のタスクを一括で削除/更新

### Won't Have（今回は実装しない）
1. **ユーザー認証機能**
   - ローカル開発環境のみで使用するため不要

2. **プロジェクト管理機能**
   - task_learning_app 側の機能に依存

3. **リアルタイム更新**
   - WebSocket は今回スコープ外

## 3. 要件定義

### 3.1 機能要件

#### FR-001: タスク一覧表示機能
- **説明**: task_learning_app の API からタスク一覧を取得し、テーブル形式で表示する
- **APIエンドポイント**: `GET http://localhost:3000/api/v1/tasks`
- **表示項目**:
  - ID（整数）
  - タイトル（文字列）
  - 期日（日付）
  - 優先度（LOW/MEDIUM/HIGH）
  - 完了状態（完了/未完了）
  - 作成日時（ISO8601形式）
- **エラー処理**:
  - API接続失敗時：「APIサーバーに接続できません」エラー表示
  - タスクが0件の場合：「タスクがありません」メッセージ表示

#### FR-002: タスク作成機能
- **説明**: フォームから入力された情報をもとに新しいタスクを作成する
- **APIエンドポイント**: `POST http://localhost:3000/api/v1/tasks`
- **入力項目**:
  - タイトル（必須、文字列）
  - 期日（必須、日付）
  - 優先度（任意、low/medium/high、デフォルト：medium）
  - プロジェクトID（任意、整数）
- **成功時の動作**:
  - フラッシュメッセージ：「✅ タスクを作成しました！（ID: XXX）」
  - タスク一覧に新しいタスクが追加される
- **失敗時の動作**:
  - バリデーションエラー：「❌ タイトルを入力してください」
  - API接続エラー：「❌ APIサーバーに接続できません」

#### FR-003: タスク更新機能
- **説明**: 既存タスクの情報を部分的に更新する
- **APIエンドポイント**: `PATCH http://localhost:3000/api/v1/tasks/:id`
- **入力項目**:
  - タスクID（必須、ドロップダウンから選択）
  - タイトル（任意）
  - 期日（任意）
  - 優先度（任意）
- **成功時の動作**:
  - フラッシュメッセージ：「✅ タスクを更新しました！（ID: XXX）」
  - タスク一覧に変更が反映される
- **失敗時の動作**:
  - タスクが存在しない：「❌ タスクが見つかりません」
  - バリデーションエラー：エラーメッセージを表示

#### FR-004: タスク削除機能
- **説明**: 指定されたタスクを削除する（論理削除）
- **APIエンドポイント**: `DELETE http://localhost:3000/api/v1/tasks/:id`
- **入力項目**:
  - タスクID（必須、ドロップダウンから選択）
- **確認ダイアログ**:
  - JavaScriptの確認ダイアログ：「本当にこのタスクを削除してもよろしいですか？」
- **成功時の動作**:
  - フラッシュメッセージ：「✅ タスクを削除しました（ID: XXX）」
  - タスク一覧から該当タスクが消える
- **失敗時の動作**:
  - タスクが存在しない：「❌ タスクが見つかりません」

### 3.2 非機能要件

#### NFR-001: パフォーマンス
- ページ読み込み時間：3秒以内
- API レスポンス時間：1秒以内

#### NFR-002: ユーザビリティ
- 直感的な UI（フォーム入力だけで操作可能）
- わかりやすいエラーメッセージ
- レスポンシブデザイン（モバイル対応）

#### NFR-003: 保守性
- コードの可読性を重視（適切なコメント、わかりやすい変数名）
- モジュール分割（APIクライアント、ルーティング、ビューを分離）

#### NFR-004: 学習性
- 詳細なドキュメント（5ファイル）を提供
- 初心者でも理解できる技術解説

## 8. リスクと対策

### リスク1: task_learning_app が起動していない
- **影響**: API通信が失敗し、全機能が使用不可
- **対策**: エラーメッセージで task_learning_app の起動を促す

### リスク2: ポート番号の衝突
- **影響**: task_api_tool が起動できない
- **対策**: ドキュメントでポート番号を明記、変更方法を記載

### リスク3: Ruby バージョンの不一致
- **影響**: gem のインストールや実行に失敗
- **対策**: セットアップガイドで Ruby バージョンの確認方法を記載
