## 3. API仕様

### 3.1 API エンドポイント一覧

| エンドポイント | HTTPメソッド | 説明 | 実装場所 |
|---------------|-------------|------|---------|
| / | GET | トップページ表示 | app.rb |
| /tasks/create | POST | タスク作成 | app.rb |
| /tasks/update/:id | POST | タスク更新 | app.rb |
| /tasks/delete/:id | POST | タスク削除 | app.rb |

### 3.2 API 詳細仕様

#### GET /

**説明**: トップページを表示し、task_learning_app からタスク一覧を取得する

**リクエスト**:
- メソッド: GET
- パラメータ: なし

**処理フロー**:
1. TaskApiClient.new でAPIクライアントを初期化
2. client.fetch_tasks でタスク一覧を取得
3. 取得結果を @tasks、@error に格納
4. erb :index でビューをレンダリング

**レスポンス**:
- Content-Type: text/html
- ステータスコード: 200 OK
- ボディ: HTMLページ

**内部API呼び出し**:
- `GET http://localhost:3000/api/v1/tasks`

---

#### POST /tasks/create

**説明**: フォームから送信されたデータをもとに新しいタスクを作成する

**リクエスト**:
- メソッド: POST
- Content-Type: application/x-www-form-urlencoded
- パラメータ:
  ```
  title: "買い物に行く"
  due_date: "2025-12-15"
  priority: "high"
  project_id: "1" (任意)
  ```

**処理フロー**:
1. フォームパラメータを受け取る
2. パラメータを JSON 形式に整形
   ```ruby
   params_hash = {
     task: {
       title: params[:title],
       due_date: params[:due_date],
       priority: params[:priority]
     }
   }
   ```
3. client.create_task(params_hash) で API 呼び出し
4. 結果に応じてフラッシュメッセージを設定
5. トップページにリダイレクト

**内部API呼び出し**:
- `POST http://localhost:3000/api/v1/tasks`
- リクエストボディ（JSON）:
  ```json
  {
    "task": {
      "title": "買い物に行く",
      "due_date": "2025-12-15",
      "priority": "high"
    }
  }
  ```

**レスポンス**:
- ステータスコード: 302 Found（リダイレクト）
- Location: /
- フラッシュメッセージ: 成功時「✅ タスクを作成しました！（ID: XXX）」

**エラーハンドリング**:
- バリデーションエラー（422）: エラーメッセージを表示
- API接続エラー: 「APIサーバーに接続できません」

---

#### POST /tasks/update/:id

**説明**: 既存タスクの情報を部分的に更新する

**リクエスト**:
- メソッド: POST
- Content-Type: application/x-www-form-urlencoded
- パラメータ:
  ```
  id: "123" (URLパラメータ)
  title: "新しいタイトル" (任意)
  due_date: "2025-12-20" (任意)
  priority: "low" (任意)
  ```

**処理フロー**:
1. URLパラメータ :id とフォームパラメータを受け取る
2. 空でないパラメータのみを JSON に含める
3. client.update_task(id, params_hash) で API 呼び出し
4. 結果に応じてフラッシュメッセージを設定
5. トップページにリダイレクト

**内部API呼び出し**:
- `PATCH http://localhost:3000/api/v1/tasks/:id`
- リクエストボディ（JSON）:
  ```json
  {
    "task": {
      "title": "新しいタイトル",
      "due_date": "2025-12-20"
    }
  }
  ```

**レスポンス**:
- ステータスコード: 302 Found（リダイレクト）
- Location: /
- フラッシュメッセージ: 成功時「✅ タスクを更新しました！（ID: XXX）」

**エラーハンドリング**:
- タスクが存在しない（404）: 「タスクが見つかりません」
- バリデーションエラー（422）: エラーメッセージを表示

---

#### POST /tasks/delete/:id

**説明**: 指定されたタスクを削除する（論理削除）

**リクエスト**:
- メソッド: POST
- Content-Type: application/x-www-form-urlencoded
- パラメータ:
  ```
  id: "123" (URLパラメータ)
  ```

**処理フロー**:
1. URLパラメータ :id を受け取る
2. client.delete_task(id) で API 呼び出し
3. 結果に応じてフラッシュメッセージを設定
4. トップページにリダイレクト

**内部API呼び出し**:
- `DELETE http://localhost:3000/api/v1/tasks/:id`

**レスポンス**:
- ステータスコード: 302 Found（リダイレクト）
- Location: /
- フラッシュメッセージ: 成功時「✅ タスクを削除しました（ID: XXX）」

**エラーハンドリング**:
- タスクが存在しない（404）: 「タスクが見つかりません」

## 4. データモデル

### 4.1 Task（task_learning_app側のモデル）

| カラム名 | データ型 | 必須 | デフォルト値 | 説明 |
|---------|---------|------|-------------|------|
| id | integer | ✅ | 自動採番 | 主キー |
| title | string | ✅ | - | タスクのタイトル |
| due_date | date | ✅ | - | 期日 |
| priority | string | - | 'medium' | 優先度（low/medium/high） |
| project_id | integer | - | null | プロジェクトID（外部キー） |
| completed_at | datetime | - | null | 完了日時 |
| deleted_at | datetime | - | null | 削除日時（論理削除） |
| created_at | datetime | ✅ | 自動設定 | 作成日時 |
| updated_at | datetime | ✅ | 自動設定 | 更新日時 |

### 4.2 バリデーションルール

- `title`: 必須（presence: true）
- `due_date`: 必須（presence: true）
- `priority`: 任意、low/medium/high のいずれか

## 5. クラス設計

### 5.1 クラス図

```
┌─────────────────────────┐
│   TaskApiClient         │
├─────────────────────────┤
│ + BASE_URL: String      │
├─────────────────────────┤
│ + fetch_tasks(): Hash   │
│ + create_task(params): Hash │
│ + update_task(id, params): Hash │
│ + delete_task(id): Hash │
│ - parse_response(response): Hash │
└─────────────────────────┘
```

### 5.2 TaskApiClient クラス仕様

#### 定数
- `BASE_URL`: "http://localhost:3000/api/v1"

#### 公開メソッド

##### fetch_tasks()
- **説明**: タスク一覧を取得する
- **戻り値**: `{ success: true, tasks: [...] }` または `{ success: false, error: "..." }`
- **HTTPメソッド**: GET
- **エンドポイント**: /tasks

##### create_task(params)
- **説明**: タスクを新規作成する
- **引数**:
  - params (Hash): タスクのパラメータ
    ```ruby
    {
      task: {
        title: "...",
        due_date: "...",
        priority: "..."
      }
    }
    ```
- **戻り値**: `{ success: true, task: {...} }` または `{ success: false, errors: [...] / error: "..." }`
- **HTTPメソッド**: POST
- **エンドポイント**: /tasks

##### update_task(id, params)
- **説明**: タスクを更新する
- **引数**:
  - id (String): タスクID
  - params (Hash): 更新するパラメータ
- **戻り値**: `{ success: true, task: {...} }` または `{ success: false, errors: [...] / error: "..." }`
- **HTTPメソッド**: PATCH
- **エンドポイント**: /tasks/:id

##### delete_task(id)
- **説明**: タスクを削除する
- **引数**:
  - id (String): タスクID
- **戻り値**: `{ success: true, message: "..." }` または `{ success: false, error: "..." }`
- **HTTPメソッド**: DELETE
- **エンドポイント**: /tasks/:id

#### 非公開メソッド

##### parse_response(response)
- **説明**: HTTPレスポンスを解析し、統一された形式で返す
- **引数**:
  - response (Net::HTTPResponse): HTTPレスポンス
- **戻り値**: Hash（統一された形式）
- **エラーハンドリング**:
  - 200/201: `{ success: true, task/tasks: ... }`
  - 404: `{ success: false, error: "..." }`
  - 422: `{ success: false, errors: [...] }`
  - その他: `{ success: false, error: "HTTPエラー: ..." }`
  - JSON::ParserError: `{ success: false, error: "JSONの解析に失敗しました" }`

## 6. テスト設計（TDD）

### 6.1 テスト方針

- **単体テスト**: 実装しない（シンプルなツールのため）
- **統合テスト**: 実装しない（GUI確認が目的）
- **手動テスト**: ブラウザで全機能を確認

### 6.2 手動テストケース

#### TC-001: タスク一覧表示
- **前提条件**: task_learning_app が起動し、タスクが2件以上存在する
- **手順**:
  1. ブラウザで http://localhost:4567 にアクセス
- **期待結果**:
  - タスク一覧テーブルが表示される
  - 各タスクのID、タイトル、期日、優先度、完了状態、作成日時が正しく表示される

#### TC-002: タスク作成（正常系）
- **前提条件**: task_learning_app が起動している
- **手順**:
  1. 「📝 タスク作成」タブを開く
  2. タイトル：「テストタスク」
  3. 期日：「2025-12-20」
  4. 優先度：「高」
  5. 「タスクを作成」ボタンをクリック
- **期待結果**:
  - 成功メッセージ「✅ タスクを作成しました！（ID: XXX）」が表示される
  - タスク一覧に新しいタスクが追加される

#### TC-003: タスク作成（異常系：タイトル空欄）
- **前提条件**: task_learning_app が起動している
- **手順**:
  1. 「📝 タスク作成」タブを開く
  2. タイトル：空欄
  3. 期日：「2025-12-20」
  4. 「タスクを作成」ボタンをクリック
- **期待結果**:
  - エラーメッセージ「❌ タイトルを入力してください」が表示される

#### TC-004: タスク更新（正常系）
- **前提条件**: タスクが1件以上存在する
- **手順**:
  1. 「✏️ タスク更新」タブを開く
  2. 更新するタスクをドロップダウンから選択
  3. タイトル：「更新後タイトル」
  4. 「タスクを更新」ボタンをクリック
- **期待結果**:
  - 成功メッセージ「✅ タスクを更新しました！（ID: XXX）」が表示される
  - タスク一覧でタイトルが更新される

#### TC-005: タスク削除（正常系）
- **前提条件**: タスクが1件以上存在する
- **手順**:
  1. 「🗑️ タスク削除」タブを開く
  2. 削除するタスクをドロップダウンから選択
  3. 「タスクを削除」ボタンをクリック
  4. 確認ダイアログで「OK」をクリック
- **期待結果**:
  - 成功メッセージ「✅ タスクを削除しました（ID: XXX）」が表示される
  - タスク一覧から該当タスクが消える

#### TC-006: API接続エラー
- **前提条件**: task_learning_app が起動していない
- **手順**:
  1. ブラウザで http://localhost:4567 にアクセス
- **期待結果**:
  - エラーメッセージ「⚠️ エラーが発生しました」
  - 「APIサーバーに接続できません。task_learning_appが起動しているか確認してください。」が表示される

## 7. セキュリティ考慮事項

### 7.1 脆弱性対策

- **XSS対策**: ERBでのHTML自動エスケープ（`<%= ... %>`）
- **CSRF対策**: 今回は不要（ローカル環境のみで使用）
- **SQLインジェクション対策**: task_learning_app側でStrong Parametersを使用
- **入力バリデーション**: task_learning_app側で実施

### 7.2 セキュリティ制約

- **認証・認可**: 実装しない（ローカル開発環境のみで使用）
- **HTTPS**: 使用しない（ローカル通信のみ）

---

## 8. パフォーマンス考慮事項

- **ページ読み込み**: タスク一覧取得は1回のAPI呼び出しで完了
- **リアルタイム更新**: 実装しない（手動で再読み込み）
- **キャッシュ**: 実装しない（常に最新のデータを取得）

---

## 9. 制約事項

- task_learning_app が http://localhost:3000 で起動していること
- task_api_tool は http://localhost:4567 で起動すること
- Ruby 3.x 以上が必要
- ブラウザは最新版のChrome、Firefox、Safariを推奨
