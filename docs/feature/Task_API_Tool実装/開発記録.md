### Phase 1: APIクライアント実装（GETのみ）

#### 目的
task_learning_app の REST API と通信するための HTTP クライアントを実装する。まずはタスク一覧取得（GET /api/v1/tasks）のみを実装。

#### 実装内容

**ファイル**: `lib/task_api_client.rb`

```ruby
require 'net/http'
require 'json'
require 'uri'

class TaskApiClient
  BASE_URL = 'http://localhost:3000/api/v1'

  def fetch_tasks
    uri = URI("#{BASE_URL}/tasks")
    response = Net::HTTP.get_response(uri)

    if response.is_a?(Net::HTTPSuccess)
      data = JSON.parse(response.body)
      { success: true, tasks: data['tasks'] }
    else
      { success: false, error: "HTTPエラー: #{response.code} #{response.message}" }
    end
  rescue Errno::ECONNREFUSED
    { success: false, error: "APIサーバーに接続できません。task_learning_appが起動しているか確認してください。" }
  rescue JSON::ParserError => e
    { success: false, error: "JSONの解析に失敗しました: #{e.message}" }
  rescue => e
    { success: false, error: "エラーが発生しました: #{e.message}" }
  end
end
```

#### 技術的判断
- **Net::HTTP を選択**: Ruby標準ライブラリで軽量、依存関係を最小限にするため
- **エラーハンドリング**: 接続エラー、JSONパースエラー、HTTPエラーを個別に処理
- **戻り値の統一**: 成功時は `{ success: true, ... }`、失敗時は `{ success: false, error: "..." }` で統一

#### 動作確認
task_learning_app が起動している状態で、Rubyコンソールから実行：
```ruby
client = TaskApiClient.new
result = client.fetch_tasks
puts result
# => { success: true, tasks: [...] }
```

### Phase 2: Sinatraアプリ実装（GET '/' のみ）

#### 目的
Sinatra で Web サーバーを起動し、トップページでタスク一覧を表示する。

#### 実装内容

**ファイル**: `app.rb`

```ruby
require 'sinatra'
require 'sinatra/reloader' if development?
require_relative 'lib/task_api_client'

enable :sessions

helpers do
  def flash
    session[:flash] ||= {}
  end
end

before do
  @flash = flash.dup
  session[:flash] = {}
end

get '/' do
  client = TaskApiClient.new
  result = client.fetch_tasks

  if result[:success]
    @tasks = result[:tasks]
    @error = nil
  else
    @tasks = []
    @error = result[:error]
  end

  erb :index
end
```

#### 技術的判断
- **Sinatra を選択**: Rails より軽量で、小規模ツールに最適
- **sinatra-contrib**: 開発時の自動リロード機能（sinatra/reloader）のために追加
- **セッション有効化**: フラッシュメッセージ機能を実装するため
- **フラッシュメッセージ**: before フィルタで前回のフラッシュを読み込み、その後クリア

# ブラウザで http://localhost:4567 にアクセス

### Phase 5: POST/PATCH/DELETE実装

#### 目的
タスクの作成、更新、削除機能を実装し、全CRUD操作を完成させる。

#### 実装内容

**ファイル**: `lib/task_api_client.rb`（追加）

```ruby
def create_task(params)
  uri = URI("#{BASE_URL}/tasks")
  http = Net::HTTP.new(uri.host, uri.port)
  request = Net::HTTP::Post.new(uri.path, 'Content-Type' => 'application/json')
  request.body = params.to_json
  response = http.request(request)
  parse_response(response)
rescue Errno::ECONNREFUSED
  { success: false, error: "APIサーバーに接続できません" }
rescue => e
  { success: false, error: "エラーが発生しました: #{e.message}" }
end

def update_task(id, params)
  uri = URI("#{BASE_URL}/tasks/#{id}")
  http = Net::HTTP.new(uri.host, uri.port)
  request = Net::HTTP::Patch.new(uri.path, 'Content-Type' => 'application/json')
  request.body = params.to_json
  response = http.request(request)
  parse_response(response)
rescue Errno::ECONNREFUSED
  { success: false, error: "APIサーバーに接続できません" }
rescue => e
  { success: false, error: "エラーが発生しました: #{e.message}" }
end

def delete_task(id)
  uri = URI("#{BASE_URL}/tasks/#{id}")
  http = Net::HTTP.new(uri.host, uri.port)
  request = Net::HTTP::Delete.new(uri.path)
  response = http.request(request)

  if response.is_a?(Net::HTTPSuccess)
    data = JSON.parse(response.body)
    { success: true, message: data['message'] }
  elsif response.code.to_i == 404
    data = JSON.parse(response.body)
    { success: false, error: data['error'] }
  else
    { success: false, error: "HTTPエラー: #{response.code} #{response.message}" }
  end
rescue Errno::ECONNREFUSED
  { success: false, error: "APIサーバーに接続できません" }
rescue => e
  { success: false, error: "エラーが発生しました: #{e.message}" }
end

private

def parse_response(response)
  if response.is_a?(Net::HTTPSuccess)
    data = JSON.parse(response.body)
    { success: true, task: data['task'] }
  elsif response.code.to_i == 422
    data = JSON.parse(response.body)
    { success: false, errors: data['errors'] }
  elsif response.code.to_i == 404
    data = JSON.parse(response.body)
    { success: false, error: data['error'] }
  else
    { success: false, error: "HTTPエラー: #{response.code} #{response.message}" }
  end
rescue JSON::ParserError => e
  { success: false, error: "JSONの解析に失敗しました: #{e.message}" }
end
```

**ファイル**: `app.rb`（追加）

```ruby
post '/tasks/create' do
  client = TaskApiClient.new
  params_hash = {
    task: {
      title: params[:title],
      due_date: params[:due_date],
      priority: params[:priority]
    }
  }
  params_hash[:task][:project_id] = params[:project_id] if params[:project_id] && !params[:project_id].empty?

  result = client.create_task(params_hash)

  if result[:success]
    flash[:success] = "✅ タスクを作成しました！（ID: #{result[:task]['id']}）"
  elsif result[:errors]
    flash[:error] = "❌ #{result[:errors].join(', ')}"
  else
    flash[:error] = "❌ #{result[:error]}"
  end

  redirect '/'
end

post '/tasks/update/:id' do
  client = TaskApiClient.new
  params_hash = { task: {} }
  params_hash[:task][:title] = params[:title] if params[:title] && !params[:title].empty?
  params_hash[:task][:due_date] = params[:due_date] if params[:due_date] && !params[:due_date].empty?
  params_hash[:task][:priority] = params[:priority] if params[:priority] && !params[:priority].empty?

  result = client.update_task(params[:id], params_hash)

  if result[:success]
    flash[:success] = "✅ タスクを更新しました！（ID: #{params[:id]}）"
  elsif result[:errors]
    flash[:error] = "❌ #{result[:errors].join(', ')}"
  else
    flash[:error] = "❌ #{result[:error]}"
  end

  redirect '/'
end

post '/tasks/delete/:id' do
  client = TaskApiClient.new
  result = client.delete_task(params[:id])

  if result[:success]
    flash[:success] = "✅ #{result[:message]}（ID: #{params[:id]}）"
  else
    flash[:error] = "❌ #{result[:error]}"
  end

  redirect '/'
end
```

## 3. Decision Log（技術的意思決定）

### DL-001: WebフレームワークにSinatraを選択

**日時**: 2025年12月13日

**決定内容**: WebフレームワークとしてSinatraを採用する

**理由**:
- **軽量**: Rails よりシンプルで学習コストが低い
- **小規模ツールに最適**: 今回のようなシンプルなWebUIには十分な機能
- **高速起動**: 開発時の再起動が速い
- **依存関係が少ない**: gem の数が少なく、セットアップが簡単

**代替案と却下理由**:
- **Rails**: 高機能だが、今回のツールには過剰（オーバーキル）
- **純粋なRack**: 低レベルすぎて開発効率が悪い

---

### DL-002: HTTPクライアントにNet::HTTPを選択

**日時**: 2025年12月13日

**決定内容**: HTTP通信に Ruby 標準ライブラリの Net::HTTP を使用する

**理由**:
- **標準ライブラリ**: 追加の gem が不要で、依存関係を最小限にできる
- **軽量**: シンプルな API 呼び出しには十分な機能
- **学習目的**: 初心者がHTTPリクエストの仕組みを理解しやすい

**代替案と却下理由**:
- **Faraday**: 高機能だが、今回のシンプルな用途には不要
- **HTTParty**: 便利だが、追加の gem が必要

---

### DL-003: テンプレートエンジンにERBを選択

**日時**: 2025年12月13日

**決定内容**: テンプレートエンジンとして ERB を使用する

**理由**:
- **Rails と同じ**: 学習の一貫性が高い
- **シンプル**: Ruby のコードをそのまま埋め込める
- **標準**: Sinatra のデフォルトで、追加設定不要

**代替案と却下理由**:
- **Haml**: よりシンプルだが、学習コストがかかる
- **Slim**: 高速だが、Rails での使用頻度が低い

## 4. 試行錯誤の記録

### 問題1: Ruby バージョンの不一致

**発生日時**: 2025年12月13日（動作確認フェーズ）

**問題内容**:
`ruby app.rb` を実行すると、システムのRuby 2.6が使用され、Sinatra が見つからないエラーが発生。

**エラーメッセージ**:
```
cannot load such file -- sinatra (LoadError)
```

**原因**:
rbenv で Ruby 3.3.0 をインストールしていたが、シェルの設定で有効化されていなかった。

**解決策**:
```bash
eval "$(rbenv init - zsh)" && rbenv shell 3.3.0 && bundle exec ruby app.rb
```

rbenv を初期化し、Ruby 3.3.0 を使用するように設定。

**学んだこと**:
- rbenv の初期化が必要（`eval "$(rbenv init - zsh)"`）
- `bundle exec` を使うことで、Gemfile に記載された gem を確実に使用できる

---

### 問題2: bundle install が未実行

**発生日時**: 2025年12月13日（動作確認フェーズ）

**問題内容**:
Ruby 3.3.0 を使用しても、Sinatra が見つからないエラーが発生。

**原因**:
`bundle install` を実行していなかったため、gem がインストールされていなかった。

**解決策**:
```bash
bundle install
```

**学んだこと**:
- プロジェクトをクローンした後は、必ず `bundle install` を実行する
- `vendor/bundle` にインストールされる

---

### 問題3: task_api_tool の起動確認

**発生日時**: 2025年12月13日（動作確認フェーズ）

**問題内容**:
`ruby app.rb` では起動しなかったが、`bundle exec ruby app.rb` では起動した。

**原因**:
`bundle exec` を使わないと、システムの gem が使用され、プロジェクト固有の gem が使われない。

**解決策**:
```bash
bundle exec ruby app.rb
```

**学んだこと**:
- Bundler を使用するプロジェクトでは、必ず `bundle exec` を付ける
- これにより、Gemfile.lock に記載された正確なバージョンの gem が使用される
